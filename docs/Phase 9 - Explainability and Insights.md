# Phase 9 - Explainability and Insights

**Status:** Implemented baseline

Implementation note:

- Backend APIs now provide the explainability input contract, mapped explanations, insight cards, financial health dashboard, credit dashboard, habit trends, improvement timeline, and monthly report generation/storage.
- SHAP/LIME from a trained production model, durable report jobs, external data connectors, and regulated decisioning remain Future Production.

## Objective

Convert CreditMiners AI outputs, engineered financial features, and historical user behavior into clear, explainable, dashboard-ready insights.

This phase should not train models, change credit scores, approve or deny lending, or provide regulated investment advice.

It should only answer:

> "Why does this financial result look this way, what changed, and what practical habit can the user understand next?"

Every insight must be traceable back to source features, model explanations, confidence, and a plain-language interpretation.

## Layer 1 - Insight Input Contract

Before generating insights, normalize all inputs into a single explainability contract.

Inputs:

- User financial profile
- Engineered financial features
- Credit score result
- Risk bucket
- Confidence score
- Top positive factors
- Top negative factors
- SHAP/LIME explanation payloads
- Investment recommendation output
- Growth projection output
- Historical feature snapshots
- Historical score snapshots

Required metadata:

- `userId`
- `sourceType`
- `sourceId`
- `modelVersion`
- `featureVersion`
- `computedAt`
- `confidence`
- `dataCompleteness`
- `explanationVersion`

Output:

```text
Validated Insight Input
```

## Layer 2 - Explanation Mapping

Convert raw model explanations into user-readable reasons.

Each explanation should include:

- Feature name
- Feature family
- Raw value
- Normalized value
- Contribution direction
- Contribution strength
- Plain-language reason
- Confidence
- Source window
- Suggested user action, when appropriate

Example:

```json
{
  "featureName": "utilityReliabilityScore",
  "direction": "POSITIVE",
  "strength": "HIGH",
  "reason": "Utility payments have been consistently on time over the last 6 months.",
  "confidence": 0.88,
  "sourceWindow": "6_MONTHS"
}
```

Explanation categories:

- Income stability
- Expense discipline
- Savings behavior
- Utility reliability
- Recharge consistency
- Digital payment behavior
- Merchant diversity
- Cash flow health
- Investment capacity
- Goal discipline

- Risk bucket
- Confidence score

- Top positive factors

- Do not present it as a lending approval or denial.

Badges can make progress visible, but they must remain educational and non-punitive.

Possible badges:

- On-Time Bill Streak
- Savings Builder
- Cash Flow Positive
- Digital Payment Consistent
- Expense Control Improved
- Goal Progress

Rules:

- Do not reveal sensitive financial details in badge names.
- Do not make badges part of credit scoring logic.
- Do not overstate financial outcomes.

---

## Layer 10 - Safety, Disclosure, and Trust

Every insight must preserve user trust.

Required safeguards:

- Show confidence when AI output is uncertain.
- Mark incomplete data clearly.
- Keep explanations plain and non-judgmental.
- Avoid deterministic financial advice.
- Include educational disclaimers for investment-related content.
- Keep all insight generation auditable.
- Preserve source feature references.

Required disclaimer pattern:

```text
This output is educational guidance based on available financial signals. It is not a credit decision, loan approval, or regulated investment advice.
```
